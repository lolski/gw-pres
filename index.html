A graph: nodes and edges

The whole data model: nodes and directed edges. Relationships are first-class — no join tables, no foreign keys. But the graph says nothing about the nodes and edges: which one is the user? what does this arrow mean?

Modeling the schema: graph types

Neo4j's best effort: typed properties, required fields, keys, implied labels (:Book => :Good), relationship endpoints. On Community edition the vocabulary is one line: CREATE CONSTRAINT … REQUIRE u.email IS UNIQUE.

Inserting goods

Multi-labels (:Good:Book) stand in for "a book is a good" — by convention, not by rule. Hold that thought.

1 · Inserting two email addresses

The uniqueness constraint doesn't even see it. A graph type's email :: STRING would catch this — but that's Enterprise 2026.02+; everywhere else, the "schema" can't say one email per user.

2 · Querying for all goods

Multi-labels are convention: nothing makes a :Book a :Good (graph types' implied labels fix this — again, Enterprise 2026.02+), so "all goods" is only as complete as everyone's memory.

3 · Querying a user whose phone may be null

"Optional" is declared nowhere — absence and typo are indistinguishable, and null propagates through three-valued logic. Bugs no tool warns you about.

Modeling the schema

The whole domain, enforced in any edition: keys, cardinality (@card(0..1) phone, @card(1..) items) and inheritance (book sub good, with good abstract).

Inserting goods

book and electronic are goods by schema — no label to remember, nothing to forget.

Inserting a user and a transaction

1 · Inserting two email addresses

Rejected at commit: email is @key — exactly one. The invalid state can't be stored, so no downstream code ever sees it.

2 · Phone may be absent — no null

Optionality is in the schema (@card(0..1)) and explicit in the query (try): $p is bound if present, absent otherwise. No null to propagate, and a typo'd attribute is a type error, not an empty column.

3 · Just electronics, just books, all goods

The polymorphic query is guaranteed complete — the schema makes every book and electronic a good; there is no "forgot the label".
